# 2.4G 外设电量查看器（漫步者 / 雷柏 / 迈从）

Windows 10/11 上读取 **2.4G 无线耳机 / 鼠标 / 键盘电量**的桌面小工具：
右下角托盘常驻图标（设备剪影 + 电池条），另有一个可选的简洁面板。
**纯 ctypes 调系统 DLL，零第三方依赖**——不用 hidapi / pystray / Pillow / pywin32，
装了 Python 就能跑，也可以打包成单个 exe（目标机无需 Python）。

这是 [yszyszysz233/2.4G-battery-viewer](https://github.com/yszyszysz233/2.4G-battery-viewer) 的 fork，
原项目针对 ATK 鼠标 + DARKRIM 耳机；本项目换成自己的三台设备，并把「设备写死」的上层改成了**配置驱动**。

## 支持的设备

只支持**下面这三台具体型号**——协议是逐台逆向出来的，不是通用 HID 电量，换别的设备不会自动识别。

| 设备 | VID:PID | 类型 | 读取方式 | 实时性 |
|---|---|---|---|---|
| **漫步者 HECATE G3 Max** | `35BB:A226` | 2.4G 耳机 | 主动查询：厂商集合 `0xFF02:0x0002`，RID `0xD0`，发 `35 BB 01 00`，回 `35 BB 0A 00 01 <电量%> <充电>` | ✅ 每次刷新实时 |
| **雷柏 VT3S** | `24AE:1411` | 2.4G 鼠标 | 纯被动：厂商集合 `0xFF00` 的 19 字节状态帧，第 8 字节电量，附带 DPI / 信号强度 | ⚠️ 鼠标有动作才上报，缓存 5 分钟 |
| **迈从 K87S** | `3837:3033` | 2.4G 键盘 | 只收推送：`0x0001:0x0000` 通道上的 `FA FB 07 <电量%> <充电>` | ⚠️ **固件不回应任何查询**，只能靠固件在充电/断电时主动播报；插拔一次充电线即可触发 |

> 迈从的查询已经彻底排除：官方格式的 getInfo / getBase / getBattery 累计发了 500+ 帧，
> `HidD_SetOutputReport` 与 `WriteFile` 两种写法都试过，Feature Report 也不存在，全部零回复。
> 官方网页驱动/桌面 HUB 同样从不查询——它们显示的其实是缓存下来的旧值。

三台的协议来源与实测记录写在各自的 `*_proto.py` 文件头和 `HANDOVER.md` 里。

**读不到时不会显示猜的数字**：三台设备都会记住最后一次成功读数，显示成
「68% · 01:36 更新（45 分钟前）」；超过 24 小时的读数只写进报错，不再当作当前电量。

## 使用方法

```bash
python my_devices.py            # 打开面板（默认自动刷新）
python my_devices.py --once     # 命令行读一次就退出
python scan.py                  # 只读盘点本机所有 HID 接口（不发一个字节）
python watch.py 24AE 3837       # 并行监听指定 VID 的接口（设备只在有动作时才上报时用）
```

### 只要托盘（不装 Python 也能跑）

```bash
build.bat                     # 双击：装 PyInstaller 并打包成 dist\电量托盘.exe
dist\电量托盘.exe             # 直接双击运行，右下角出现电量图标
```

- 单文件 8 MB 左右，**目标机不需要装 Python**
- 图标：**上半是设备剪影**（耳机 / 鼠标 / 键盘），**下半是电池条**（绿 ≥60 / 黄 30–59 / 红 <30），
  不挤数字也能一眼分清是哪台设备、大概剩多少电；精确百分比和更新时间在悬停提示里
- 左键立刻刷新，**右键出菜单**（立即刷新 / 开机自启 / 退出）
- 配置写在 exe 同目录的 `tray_config.json`（不是临时解包目录）
- 读不到时显示**上次读数 + 更新时间**（如「68% · 01:36 更新（45 分钟前）」），数据存在同目录 `device_last.json`
- 开机自启会写「启动」文件夹里指向 exe 的快捷方式，任务管理器可见
- 打 exe 时没有面板，「打开面板」菜单项会自动隐藏

面板里每台设备一张卡片，显示百分比 + 进度条 + 数据来源；底部可以改刷新间隔。

## 逆向这几个协议时踩到的坑

1. **Windows 的 `HidD_SetOutputReport` 会把第 0 字节当「报告 ID」剥掉**，
   而 Linux 的 hidraw 是原样发送。照抄别人（Linux）抓到的报文时，
   常常要**多补一个字节**才对得上，否则设备完全不响应。
2. **长度必须正好等于 `OutputReportByteLength`**，写短了 Windows 直接拒绝（err=87），
   一个字节都不会下发。
3. **Windows 会在下发前校验报告 ID**：
   - err=87 → 这个报告 ID 不存在
   - err=1 → 这个 ID 存在，但不是输出报告（多半是输入报告）
   拿错误码当探针，可以安全地把「哪个集合用哪个报告 ID」试出来。
4. **同一 HID 句柄上并发「阻塞读 + 写」会直接杀掉进程**（连异常栈都没有）。
   正确做法是独立的、带 `FILE_FLAG_OVERLAPPED` 的读句柄 + 事件超时 + `CancelIoEx`。
5. **系统独占的顶层集合**（鼠标/键盘/笔/触摸屏）只能用 `dwDesiredAccess=0` 打开，
   能读属性和 Feature Report，但不能发指令 —— 所以本项目永远不会写坏键鼠。
6. **官方软件的日志是最好的协议来源**：HECATE 把每次 HID 收发都打成十六进制，
   直接抄，比盲猜快十倍。
7. **固件可能只在特定时机上报**（充电、切换模式、鼠标移动）。
   读不到就返回空并缓存上一次的值，**绝不显示猜的数字**。

## 环境要求

- Windows 10 / 11
- Python 3.10+（需要 `tkinter`，官方安装包默认自带）

## 隐私

- **不联网**：没有任何 http / socket / urllib / 遥测调用，所有读取都在本地 HID 层完成。
- **不写日志**：默认不产生任何日志文件；只有 `--debug` 时才往控制台打印。
- **不上传**：设备序列号、地址等信息只在内存里用，不落盘。

## 说明

私有协议部分是通过逆向厂商软件 + 抓包分析得到的，仅供学习与个人使用。
